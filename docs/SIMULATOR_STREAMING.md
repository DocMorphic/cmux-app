# Simulator streaming implementation and remaining work

Reference: cmux `4c5272e9153eca2033c9f40ac749f0c3a5bcb291`.
This is a required feature, not an Android platform exception. The current
checkpoint is infrastructure; **there is no usable simulator viewer yet**.

## Source contract

`WorkspaceDetailView+Surfaces.swift` selects v2 when `simulator.stream.v2`, an
Iroh route and lane provider are available. It stops legacy streaming when v2
mounts. Other supported hosts use the legacy simulator RPC/frame path. Device
listing/switching and worker recovery have separate capability gates.

The v2 provider in `MobileIrxRuntimeComposition+Streams.swift` opens an independent
bidirectional lane on the admitted peer: lane `simulator_stream`, resource
`simstream:<lowercase panel UUID>`. There is no JSON simulator RPC on this lane.
`SimStreamProtocol.swift` defines big-endian length-framed binary messages, an
8 MiB body limit, HEVC/H.264 configs and AVCC/HVCC length-prefixed NAL payloads.
The host is credit limited by acknowledgements of presented frames. Reconnect
starts fresh; old input and partial messages must not transfer to another lane.

## Implemented prerequisite

- `SimStreamWire`: all eight message types and every input kind, full UInt64
  epochs/sequences/timestamps, raw float fields, codec/parameter sets, and strict
  UTF-8/trailing/enum/length checks. Unknown *preferred* codecs are skipped as in
  Swift; unknown configured codecs fail. Receive chunks are bounded at 64 KiB,
  with at most one declared message body retained. Partial EOF is an error.
- `IrxSimulatorLane`: exact canonical panel descriptor on the admitted session,
  permission checks before/after I/O, cancellation and independent lane cleanup.
  `MobileRpcClient.useSimulatorLane` borrows the caller's lease; late opening
  candidates are closed after lease cancellation without closing other leases.
- `SimStreamSession`: one attach owns its input queue and presentation callbacks.
  Start precedes input. Acknowledgements are sent only when the presenter returns
  true. Three consecutive rejected frames request one keyframe; six terminate the
  attempt. Host-sent viewer messages and pre-config frames fail closed. All exits
  discard input and retire the lane; instances cannot be reused for reconnect.
- `SimInputOutbox`: only unsent move events for the same pointer coalesce, without
  crossing a phase/key/text/button boundary. Batches retain increasing sequence
  numbers. Bounded-queue overflow terminates the session instead of silently
  losing a touch-up or replaying stale input later.
- `SimViewerLifecycle`: the pinned activation/transport/retry/background/refresh
  policy, 250 ms–4 s bounded backoff, reset after actual presentation, and no
  automatic retry into a host-declared unavailable panel. Its owner still needs
  wiring and generation fencing.

## Verification — 2026-09-30

22 focused JVM tests pass: 11 simulator wire/session/lane tests, three lifecycle
tests, and eight existing terminal input/lease tests. These verify:

- Nine golden fixtures generated by **compiling and executing the unmodified
  upstream Swift codec**, including both video codec configs, UInt64 maximum
  values, all touch phases/hardware buttons and Unicode text.
- Reassembly across every split point and one-byte chunks; malformed/truncated/
  oversized streams and invalid UTF-8; future codec negotiation.
- No ack before presentation; keyframe recovery and termination on display
  rejection; invalid host direction; dropped pending input on cancellation;
  exact lane resource and late lane cancellation under a shared RPC lease.
- Input coalescing/ordering/queue bounds, retry cap, presentation-based backoff
  reset, background cancellation and terminal host-state recovery.

`app/src/test/resources/simulator/wire.json` records source SHA-256 hashes.
Reproduce with:

```sh
python3 scripts/generate-simulator-wire-fixtures.py --source /path/to/cmux
JAVA_HOME=/path/to/jdk17 ./gradlew :app:testDebugUnitTest \
  --tests '*SimStreamTest' --tests '*SimViewerLifecycleTest' \
  --tests '*IrxTerminalInputLaneTest'
```

The session uses a test presenter in these checks. No real video decoding,
Android surface rendering, Mac simulator lane, or physical Pixel acceptance is
proven. Do not count these tests as a finished simulator feature.

## Next implementation steps

1. Implement an Android MediaCodec presenter for HEVC/H.264 with validated
   dimensions/parameter sets, AVCC/HVCC-to-Annex-B conversion, Surface ownership,
   output presentation acknowledgement, decoder reset and full release.
   Compare with `SimStreamSampleBufferFactory`, `SimStreamDisplayView`, and
   `SimStreamViewerEngine`; test real encoded frames and actual displayed pixels.
2. Add the production lifecycle owner: current-client/lease binding, attach epochs,
   timer/generation fencing, watchdog, foreground/background, explicit refresh,
   quality changes and host status. Use `SimulatorStreamV2Store`,
   `SimStreamQualityPreset`, and `SimStreamViewerLifecycle` as the reference.
3. Parse simulator descriptors and wire surface selection. Build the pane with
   aspect-fit touch mapping, hardware buttons, text/key input, quality controls,
   device switcher and recovery. Audit `SimulatorStreamV2Pane`,
   `SimStreamTouchMapping`, `MobileSimulatorRPCDTOs`, and simulator RPC methods.
4. Implement the legacy RPC/image path required for hosts without v2. Audit
   `MobileShellComposite+SimulatorStream`, `SimulatorStreamPane`, coordinate,
   presentation/staleness policies, stop behavior and separate capability gates.
5. Exercise both paths against framed/native lane fixtures, then a dedicated real
   Mac simulator and the Pixel. Verify reconnect/background, rotation, input
   ordering, device switching, worker recovery, quality and UI parity.

These steps retain the full iOS behavior. A fallback card, a still-image-only v2
viewer, or passing protocol fixtures would not meet that scope.
